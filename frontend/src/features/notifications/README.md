# features/notifications

اعلان‌های تخصیص Task در صفحهٔ `/notifications` و پیش‌نمایش هدر دسکتاپ نمایش داده می‌شوند. صفحه تب ثابت «تسک‌های خوانده‌نشده»، گروه‌بندی پروژه و فیلترهای نام‌دار دارد. فیلتر نام‌دار بر اساس عامل، نوع مقصد و اولویت Task تعریف می‌شود و به‌ازای `CurrentUser.id` در localStorage ذخیره می‌شود؛ اولویت Task در API همراه اعلان برگردانده می‌شود. هنگام ساخت Task برای مسئولان، بک‌اند رکورد پایدار می‌سازد؛ کلیک روی اعلان آن را خوانده و workspace جزئیات همان Task را باز می‌کند.

## اجزا

- `notification-format.ts`: نگاشت متن رخداد، فرمت زمان سروری و مقصد کلیک. مقصد Task به `/tasks/[taskId]` می‌رود.
- `notifications-preview-dialog.tsx`: ردیف‌ها و تب‌های پروژه را میان `NotificationsFullPage` و `NotificationsPreviewDialog` مشترک می‌کند؛ صفحهٔ کامل فیلترهای نام‌دار و تب تسک‌های خوانده‌نشده را نیز مدیریت می‌کند. صفحهٔ کامل دکمهٔ تنظیمات ندارد؛ پیش‌نمایش هدر دسکتاپ لینک تنظیمات دارد.
- `notification-list.tsx`: پیاده‌سازی قدیمی فیلترهای همه/خوانده‌شده/تایید است و دیگر مصرف‌کنندهٔ مسیر اصلی نیست.

## وابستگی‌ها و مصرف‌کننده‌ها

- `lib/api/notifications.ts` برای خواندن و علامت‌گذاری اعلان؛ `lib/api/tasks.ts` برای ثبت Task با هویت سازنده؛ تایپ‌ها در `lib/api/types.ts`.
- API بک‌اند در `backend/apps/notifications/notification-repository.js` و جدول `notifications` در SQLite. چون Auth وجود ندارد، گیرنده با نام کاربر جاری فیلتر می‌شود.
- `/notifications` و `BottomTabBar` صفحهٔ کامل را مصرف می‌کنند؛ `DesktopHeader` پیش‌نمایش را مصرف می‌کند.
- در حال حاضر فقط تخصیص Task اعلان تولید می‌کند؛ کامنت و دیگر تغییرات هنوز اعلان نمی‌شوند. تنظیمات تایید نیز در این فاز کامل نیست.
- `backend/seed-team-demo.js` داده‌های نمونهٔ اعلان تخصیص تسک را برای اعضای تیم می‌سازد تا تب خوانده‌نشده و فیلترها داده داشته باشند.

نشان تب فعال در امتداد خط جداکنندهٔ پایین نوار قرار می‌گیرد.
