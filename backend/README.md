# Backend

سرویس Node.js برای ورود نشست‌محور و ذخیرهٔ پایدار داده‌های Quire در SQLite. HTTP با `node:http` و دیتابیس با ماژول داخلی `node:sqlite` اجرا می‌شوند.

## اجرا

```bash
npm run dev
npm run setup:admin
npm run seed:demo
npm run seed:report-demo
```

نیازمند Node.js 22.13 یا جدیدتر است. در اجرای نخست، `npm run setup:admin` حساب اولیه را در دیتابیس خالی می‌سازد و رمز را بدون نمایش در ترمینال می‌گیرد. API روی `http://127.0.0.1:4000` اجرا می‌شود و Next مسیر `/api/v1` را به آن می‌فرستد. جزئیات env، schema، endpointها و مسیر مهاجرت در [docs/BACKEND.md](../docs/BACKEND.md) ثبت شده است.

## مسئولیت ماژول‌ها

- `server.js`: ورودی HTTP، اعتبارسنجی درخواست، routeها و قالب خطاهای API.
- `database.js`: بازکردن SQLite، foreign keyها و اجرای migrationهای نسخه‌بندی‌شده؛ seed فقط با انتخاب صریح فعال می‌شود.
- `seed-demo.js`: ساخت صریح حساب‌ها و داده‌های نمونهٔ سازمانی/کاری برای محیط محلی؛ رمز حساب‌های نمونه را یک‌بار چاپ می‌کند و هیچ‌وقت به‌طور خودکار اجرا نمی‌شود.
- `seed-report-demo.js`: افزودن داده‌های تکمیلی گزارش به دیتابیس محلی تا ۳۶ تسک و ۱۸ تیکت با شمارش متوازن وضعیت‌ها؛ در اجرای دوباره چیزی اضافه نمی‌کند.
- `apps/auth/`: حساب اولیه، هش رمز با scrypt، نشست‌های ۳۰روزه و ابطال نشست.
- `apps/organizations/`: سلسله‌مراتب و مالکیت سازمان، معاونت و پروژه.
- `task-repository.js`: عملیات پایگاه داده و تبدیل سطرها به قرارداد Task فرانت.
- `apps/tickets/ticket-comment-repository.js`: خواندن/ثبت کامنت‌های تیکت در SQLite با زمان ایجاد سروری.
- `apps/projects/project-page-repository.js`: ذخیرهٔ یک سند و یک چت برای هر پروژه و پیام‌های چت؛ مسیرهای آن در `docs/BACKEND.md` آمده‌اند.
- `apps/notifications/notification-repository.js`: ایجاد اعلان پایدار برای مسئولان هنگام ساخت/تخصیص تسک و نگهداری وضعیت خوانده‌شدن.
- `migrations/`: schema تکامل‌پذیر؛ migration اعمال‌شده را ویرایش نکنید.
- `test/`: تست‌های داخلی Node روی پایگاه موقت.

دیتابیس اجرای سرویس خودکار دادهٔ دمو نمی‌گیرد. حساب نخست با `npm run setup:admin` ساخته می‌شود؛ برای محیط محلی می‌توان بعد از آن `npm run seed:demo` را اجرا کرد تا سه حساب نمونه با آواتار و یک مجموعهٔ کوچک شامل یک سازمان، دو معاونت، سه پروژه، ۹ تسک، سه تیکت و ۱۲ اعلان تخصیص اضافه شوند. تیکت‌های نمونه را حساب اولیه ساخته است تا در کارتابل او دیده شوند؛ اعلان‌ها نیز برای مسئولان نمونه ساخته می‌شوند. رمزهای تصادفی حساب‌های نمونه فقط یک‌بار در خروجی همان دستور چاپ می‌شوند. APIهای داده نشست معتبر می‌خواهند؛ cookie نشست `HttpOnly`, `SameSite=Lax` است و در production به‌طور پیش‌فرض `Secure` می‌شود.

برای گزارش محلی، پس از `seed:demo` می‌توان `npm run seed:report-demo` را اجرا کرد. این seed مستقل به تعداد لازم تسک و تیکت فارسی به پروژه‌های موجود اضافه می‌کند تا جمع به ۳۶ تسک (۱۲ مورد در هر وضعیت) و ۱۸ تیکت (۶ مورد در هر وضعیت) برسد. در دیتابیس گزارش فعلی، این یعنی افزودن ۲۱ تسک و ۱۲ تیکت. اجرای دوباره هیچ رکورد تکراری نمی‌سازد.

`seed-team-demo.js` مجموعهٔ اختیاری نمونه شامل ۱۰ کاربر، یک سازمان، دو معاونت، چهار پروژه، ۴۰ تسک و ۱۰۰ تیکت می‌سازد. ورودی آن مسیر فایل JSON حساب‌هاست که باید خارج از Git و با مجوز محدود نگه‌داری شود؛ فقط برای دیتابیسی اجرا شود که شناسه‌ها و ایمیل‌های نمونه در آن وجود ندارند. پیش از اجرا از SQLite پشتیبان بگیرید. تصویر حساب‌ها از فایل‌های WebP فشردهٔ `frontend/public/avatars/team/` در باندل وب ارائه می‌شود.
