# Organizations

این ماژول سازمان، تنظیمات عمومی و گزینه‌ها، عضویت و مجوزهای سازمانی، معاونت، پروژه و فید فعالیت سازمان را در SQLite مدیریت می‌کند. slug سازمان و slug پروژه در همان سازمان یکتا هستند و endpointهای مسیر خوانا فقط پس از بررسی عضویت داده می‌دهند. سازمان یک owner یکتا، admin با مجوز محدود مدیریت دسترسی و اعضای custom با مجموعهٔ مجوزهای پایدار دارد. انتقال مالکیت در یک transaction انجام می‌شود؛ API هیچ‌گاه سازمان را بدون owner نمی‌گذارد. نام، توضیحات، تصویر محدودشده و slug در دیتابیس ذخیره می‌شوند. `division_members` اعضای منتخب هر معاونت را از میان اعضای همان سازمان نگه می‌دارد، اما دسترسی پروژه را عوض نمی‌کند؛ عضویت سازمان همچنان لازم است. `organization-activity-repository.js` رخداد ساخت تسک، تغییر وضعیت و کامنت را ثبت می‌کند؛ صفحه‌بندی از cursor پایدار SQLite استفاده می‌کند و endpoint فعالیت فقط به اعضای سازمان پاسخ می‌دهد. مجوزهای ساخت/ویرایش hierarchy و مدیریت اعضا سمت سرور بررسی می‌شوند. دعوت در نسخهٔ فعلی به حسابی که از قبل در سامانه وجود دارد وصل می‌شود.

`PATCH /organizations/:organizationId/divisions/:divisionId/settings` نام و اعضای منتخب معاونت را با مجوز `editDivision` ذخیره می‌کند؛ اعضا باید عضو همان سازمان باشند و این roster به‌تنهایی دسترسی پروژه نمی‌دهد. ساخت معاونت اعضای فعلی سازمان را به‌طور پیش‌فرض انتخاب می‌کند؛ انتقال معاونت فقط اعضای مشترک با سازمان مقصد را نگه می‌دارد. `PATCH /projects/:projectId/settings` نام و توضیحات پروژه را با مجوز `editProject` ذخیره می‌کند؛ slug پروژه هنگام ویرایش ثابت می‌ماند.

مخزن `organization-activity-repository.js` برای پروژه شمارش روزانهٔ UTC رخدادهای ثبت‌شدهٔ ساخت تسک و تغییر وضعیت را به تفکیک عامل، برای تسک‌های موجود در همان پروژه، برمی‌گرداند. این شمارش تاریخچهٔ کامل همهٔ فعالیت‌ها یا تسک‌های حذف‌شده نیست. مسیر HTTP دسترسی پروژه را پیش از خواندن بررسی می‌کند.

`project-status-history.js` وضعیت پایان هر روز تسک‌های موجود را برای نمودار ۱۲روزه از وضعیت فعلی و رخدادهای تغییر وضعیت ثبت‌شده بازسازی می‌کند. تاریخچهٔ تسک حذف‌شده و تغییراتی که در پایگاه ثبت نشده‌اند قابل بازسازی نیستند؛ `server.js` تنها پس از بررسی عضویت پروژه خروجی را می‌دهد.

وابستگی‌ها: جداول `users`, `organizations`, `organization_members`, `project_members`, `division_members`, `organization_activity`, `divisions`, `projects` و migrationهای `008_organizations_and_divisions.sql`, `010_organization_settings_and_members.sql`, `011_organization_activity.sql`, `012_division_members.sql`, `015_project_members.sql`. مسیرهای HTTP در `server.js` آن را مصرف می‌کنند. فرانت‌اند `lib/api/organizations.ts`, `projects.ts` و `features/organizations/organization-activity-feed.tsx` و درخت `features/projects/organization-project-tree.tsx` از این API استفاده می‌کنند.

`project_members` دسترسی پروژه را به عضویت هم‌زمان در سازمان و پروژه محدود می‌کند. migration 015 همهٔ اعضای فعلی سازمان را به پروژه‌های موجود اضافه می‌کند؛ سازنده عضو پروژهٔ جدید است. افزودن عضو با مجوز `editProject` و پس از کنترل عضویت سازمان انجام می‌شود. انتقال پروژه یا معاونت فقط اعضای مشترک سازمان مقصد را نگه می‌دارد. عضو قابل‌دسترسی jobTitle، skills و bio دارد؛ دستیار برای پیشنهاد مسئول این داده را می‌خواند.
